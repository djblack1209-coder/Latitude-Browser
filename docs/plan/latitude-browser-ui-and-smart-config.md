# Latitude Browser：UI 设计、功能整理与智能配置方案

> 文档状态：产品方案（本轮只做方案整理，不落地自动配置业务逻辑）
> 方案日期：2026-09-04
> 适用范围：桌面端 Wails + React 应用

## 0. 先把需求翻译成产品目标

当前需求不是简单地“加一个按钮”，而是要把一个设置项很多、第一次使用门槛较高的指纹浏览器，重构成：

- **新手能在 3 分钟内创建第一个可用实例**；
- **熟悉用户仍然能控制细节**，但复杂度默认不打扰；
- **指纹配置强调一致性和可解释性**，不承诺“绝对不可检测”；
- **代理、浏览器内核、语言时区、屏幕和硬件参数互相匹配**，减少配置冲突；
- **每一次自动建议都可预览、可回滚、可手动覆盖**。

产品定位建议：

> **Latitude Browser = 面向多账号隔离、隐私测试和本地浏览器实例管理的智能指纹浏览器工作台。**

“黑客感”用于建立识别度和氛围，不用于堆砌绿色字符、终端动画或难以理解的术语。

## 1. 当前项目审计结论（As-is）

当前仓库已经具备较完整的基础能力：实例管理、代理池、内核、插件、书签、标签、自动化脚本、日志和系统设置。现有侧边栏更像“开发者后台”，主要问题是：

1. **没有明确的新手起点**：用户进入后不知道应该先配代理、先建实例还是先改默认指纹。
2. **实例创建和高级参数耦合**：首次使用会被大量字段打断。
3. **代理与指纹没有被同一条流程解释**：用户容易出现网络位置、语言、时区、UA、屏幕组合不一致。
4. **状态反馈偏弱**：缺少“已配置、存在冲突、需要检查、可直接启动”等明确状态。
5. **视觉上偏浅色管理后台**：与“隐私、隔离、设备指纹”心智不一致，也缺少产品记忆点。

本方案不直接重写已有业务页面，而是先定义信息架构、组件规范和自动配置逻辑，后续按 MVP 分阶段实现。

## 2. 新版信息架构（To-be）

### 2.1 侧边栏结构

“自动配置”固定在侧边栏顶部，并与其他导航视觉隔离。建议使用 `WandSparkles` 图标和绿色状态点，而不是普通列表项。

```text
[Latitude Browser 标识]

  ⚡ 自动配置                         新手首选

工作台
  实例总览                           默认首页
  最近使用
  待处理 / 有冲突

网络与代理
  代理池
  连接栈
  网络诊断

指纹资产
  指纹模板
  浏览器内核
  插件包
  书签与标签

自动化
  自动化脚本
  运行记录

系统
  全局设置
  文档中心
  日志与诊断
```

### 2.2 路由建议

| 现有能力 | 建议显示名称 | 建议路由 | 说明 |
|---|---|---|---|
| `/browser/list` | 实例总览 | 保留 | 作为默认工作台，不强行更换已有数据结构 |
| 新增 | 自动配置 | `/browser/auto-config` | 专用向导页，不用弹窗承载完整流程 |
| `/browser/proxy-pool` | 代理池 | 保留 | 增加连接栈筛选和健康状态 |
| 新增 | 连接栈 | `/browser/connector` | 明确 Xray + sing-box 组合栈与独立 Mihomo 栈 |
| 新增 | 网络诊断 | `/browser/network-diagnostics` | 聚合连通性、DNS、WebRTC、IPv6 和地理位置检查 |
| `/browser/cores` | 浏览器内核 | 保留 | 在实例详情内显示兼容性 |
| `/browser/extensions` | 插件包 | 保留 | 不与首次实例创建混在一起 |
| `/browser/tags` + `/browser/bookmarks` | 书签与标签 | 可合并入口，保留子页 | 降低侧边栏数量 |
| `/browser/automation` | 自动化脚本 | 保留 | 运行记录从脚本编辑页中独立出来 |
| `/settings` | 全局设置 | 保留 | 只放应用级默认项，不放单实例指纹字段 |
| `/browser/logs` | 日志与诊断 | 保留 | 默认隐藏技术细节，支持复制诊断摘要 |

### 2.3 “高级设置”的归属原则

不要再做一个让用户猜含义的“全部高级设置”页面。采用两层归属：

- **全局设置**：主题、语言、自动保存、日志级别、默认启动策略、默认连接栈。
- **实例设置**：该实例的代理、指纹、时区、存储、启动参数、自动化和诊断。

实例设置顶部先放“配置摘要”，下面再按分组折叠：

1. 网络与代理
2. 指纹与浏览器标识
3. 语言、时区与地理位置
4. 屏幕、图形与硬件能力
5. Cookie、存储与会话
6. 启动与性能
7. 自动化与调试
8. 诊断与回滚

每个字段显示来源标签：`自动建议`、`继承全局`、`手动覆盖`、`检测到冲突`。

## 3. UI 视觉方案：Cyberpunk，但先让用户看懂

### 3.1 视觉主题

**主题名：Latitude / Signal Noir**

- 基底：OLED 深黑、墨灰面板、细网格或极弱噪点纹理；
- 主色：低饱和荧光绿，仅用于主要行动、在线状态和选中状态；
- 辅色：琥珀色表示建议/待确认，红色表示冲突/危险，蓝灰色表示信息；
- 终端感只出现在诊断摘要、状态码、实例 ID 等局部区域；
- 不使用满屏渐变、炫光背景、闪烁字符或“伪黑客”装饰。

### 3.2 颜色令牌

| 令牌 | 色值 | 用途 |
|---|---|---|
| `bg.canvas` | `#080A0B` | 应用底色 |
| `bg.surface` | `#111417` | 侧边栏、卡片、抽屉 |
| `bg.elevated` | `#181D20` | 弹层、步骤卡、输入区 |
| `border.default` | `#293136` | 分隔线、输入框边界 |
| `text.primary` | `#E7F1EA` | 主文案 |
| `text.secondary` | `#AAB8AE` | 次要文案 |
| `accent.green` | `#63FF8A` | 主按钮、成功、选中 |
| `accent.greenMuted` | `#1F8F4D` | 背景提示、弱状态 |
| `accent.amber` | `#FFB84D` | 自动建议、待确认 |
| `accent.red` | `#FF6262` | 冲突、删除、风险 |

绿色不用于大段正文，保证对比度和信息层级。

### 3.3 字体与密度

- UI 正文：`IBM Plex Sans` 或系统无衬线回退；
- 技术信息、实例 ID、状态码：`JetBrains Mono`；
- 主要标题不使用等宽字体，避免整个应用像终端；
- 8px 基础间距；表格行高不低于 44px；可点击目标不小于 36px；
- 只使用少量圆角（8px 或 10px），不做“每个元素都是胶囊”的卡片墙。

### 3.4 核心页面布局

**应用壳层**

- 左侧栏：240px，可收缩到 64px；
- 顶部栏：56px，显示当前工作区、搜索/命令入口、通知和当前连接状态；
- 内容区：最大宽度 1440px，页面内使用明显的主次列；
- 右侧抽屉：承载短表单和诊断详情，不用来承载完整向导。

**实例总览**

- 顶部一条“当前环境摘要”：系统、浏览器内核、连接栈、最近诊断时间；
- 主操作只有两个：`自动配置`、`新建实例`；
- 实例列表支持状态筛选：`可启动`、`需检查`、`离线`、`草稿`；
- 每行只展示最重要的 5 项：名称、代理位置、指纹兼容状态、上次启动、操作；
- 复杂字段在实例详情中查看，不塞进表格。

**自动配置页**

- 左：4 步流程导航；
- 中：当前步骤的主要决策卡；
- 右：实时“配置摘要”面板；
- 底部固定操作栏：`上一步`、`保存草稿`、`继续`/`应用并检查`。

### 3.5 组件清单

- `AutoConfigEntry`：侧边栏置顶入口，带“推荐”标记；
- `ConfigStepper`：4～5 步，不超过 5 个主步骤；
- `ModeChoiceCard`：代理配置 / 直连二选一；
- `FingerprintSummary`：显示稳定字段、轮换字段、来源和兼容性；
- `ConsistencyScore`：显示“稳定 / 需关注 / 存在冲突”，不要伪装成绝对安全百分比；
- `ConfigDiffPanel`：应用前展示将要写入的变化；
- `AdvancedAccordion`：只展开当前需要处理的分组；
- `StatusBadge`：统一使用状态文字，不能只依赖颜色；
- `DiagnosticTimeline`：按时间展示检测、修复和回滚事件。

### 3.6 动效原则

- 页面切换 150～220ms，使用 opacity + translate；
- 步骤切换只做轻微滑入，不做全屏扫描线；
- “正在检测”使用静态进度条或微弱呼吸，不使用高频闪烁；
- 所有动效支持减少动态设置（`prefers-reduced-motion`）。

## 4. 自动配置流程（用户视角）

### Step 1：选择网络方式

进入自动配置后只问一个问题：

> **这次实例如何连接网络？**

两个主卡片：

1. **创建代理配置**（推荐用于需要独立网络环境的实例）
   - 从代理池选择已有节点；
   - 导入订阅或粘贴单节点；
   - 手动配置协议作为兜底；
   - 自动进行连通性、延迟、出口位置检查。
2. **直连**（推荐用于本地测试或不需要代理的场景）
   - 明确显示“将使用当前设备网络出口”；
   - 后续仍然执行本地网络和 WebRTC 诊断。

连接栈必须显式显示：

- `Xray + sing-box 组合栈`：Xray 负责 vmess/vless/trojan/shadowsocks/链式代理，sing-box 负责 hysteria2/tuic/anytls；
- `独立 Mihomo 栈`：只使用 Mihomo 管理和启动对应协议；
- 禁止自动在两套栈之间混用，冲突时给出可理解的修复建议。

### Step 2：采集本机基线

采集默认在本机完成，先解释用途并允许用户跳过可选字段。

**浏览器和系统基线**

- OS 平台和版本族；
- 浏览器内核版本、UA 和 UA-CH 可用性；
- 系统语言、浏览器语言、时区；
- 屏幕尺寸、可用工作区、DPR、色深；
- CPU 核心数、内存并发能力；
- WebGL vendor/renderer、Canvas、Audio、Client Rects 能力；
- 字体可用性、媒体设备数量（只保留摘要，不默认保存原始值）。

**网络基线**

- 出口 IP、国家/地区、ASN（仅摘要）；
- DNS、IPv4/IPv6、WebRTC 路径；
- 代理握手和真实连通性；
- 连接栈和代理协议是否匹配。

界面文案应使用“读取本机能力用于生成一致配置”，不要写成“窃取指纹”或“100% 隐身”。

### Step 3：生成一致性建议

将信息放入一致性规则图，而不是简单随机抽取字段。规则优先级：

1. **硬约束**：不能生成明显不可能的组合，例如平台声明、浏览器内核和 UA 完全冲突。
2. **网络约束**：代理出口位置与语言/时区明显冲突时标为待确认。
3. **硬件约束**：屏幕、DPR、色深、WebGL 和字体组合应来自可行的设备簇。
4. **稳定性约束**：登录身份相关字段默认保持稳定，避免每次启动都变化。
5. **用户偏好**：用户手动覆盖的字段优先级最高，但显示可能产生的影响。

输出不是“神秘指纹”，而是一张可解释摘要：

```text
设备簇       Windows / Chrome 140 / 1920×1080 / DPR 1.0
网络出口     新加坡 / IPv4 / Xray + sing-box
语言时区     en-US / Asia-Singapore
稳定字段     UA、平台、屏幕、时区、WebGL 族
可轮换字段   Canvas 噪声种子、Audio 噪声种子、低风险字体子集
需要确认     系统语言与出口位置差异较大
```

### Step 4：保存到当前页面并检查

- 先保存为**草稿实例**，不自动覆盖其他实例；
- 显示 `配置差异`：新增了哪些字段、哪些来自本机、哪些来自代理；
- 运行健康检查：启动参数、代理连通性、DNS、WebRTC、IPv6、浏览器页面可达性；
- 允许 `应用配置`、`返回修改`、`保存但稍后检查` 三种结果；
- 检查失败时保留诊断摘要和一键回滚入口。

### Step 5：选择指纹模式

配置检查完成后再询问：

- **固定指纹**：适合长期登录、账号连续性、稳定复现测试；
- **随机指纹**：在同一兼容设备簇中受约束轮换，适合需要降低长期静态特征的场景。

随机模式不能被设计成“每个请求都变”。默认轮换策略建议：

- 每次启动；
- 每天一次；
- 手动轮换；
- 自定义时间（高级设置）。

高风险或身份相关字段（平台、UA、屏幕、时区、WebGL 族）默认不随机；只对低风险字段做小范围轮换，并显示“上次轮换时间”和“下次计划”。

## 5. 智能配置引擎：实现规则而不是“随机参数生成器”

### 5.1 配置对象建议

后续实现可以抽象成以下结构（名称可调整）：

```text
FingerprintPolicy
├─ mode: fixed | constrained-random
├─ source: local-baseline | template | manual
├─ stableFields[]
├─ rotatingFields[]
├─ rotationSchedule
├─ compatibilityCluster
├─ networkBinding
├─ overrides[]
├─ conflicts[]
└─ diagnostics
```

### 5.2 建议的评分模型

评分目的不是宣称“不可检测”，而是提示用户配置是否自洽：

- **稳定**：没有硬冲突，网络与设备信息基本匹配；
- **需关注**：存在软冲突，例如语言/时区与出口地区差异；
- **存在冲突**：存在硬冲突，例如 UA、平台、内核参数互相矛盾；
- **无法检查**：缺少代理或权限不足，不把未知误判为安全。

评分必须可解释：每个扣分项有“原因”和“修复”按钮。

### 5.3 代理连接栈守则

- `browser.default_connector_type=xray` 时，按 Xray + sing-box 组合栈执行；
- `browser.default_connector_type=mihomo` 时，按独立 Mihomo 栈执行；
- 实例启动、测速、真实连通性、IP 健康、预热和代理下载使用同一连接栈；
- 不能把 sing-box 协议错误标记成“Xray 不支持”；
- 切换连接栈后必须重新测速和重新进行泄漏检查。

### 5.4 隐私和数据保留

- 原始设备指纹默认只在本机内存中短暂使用；
- 持久化时优先保存“派生配置”和兼容性摘要，不保存不必要的原始值；
- 代理密码、Token、Cookie 等敏感字段禁止进入普通日志；
- 诊断导出必须脱敏，并明确提示将导出哪些字段；
- 自动配置写入前必须有配置差异预览和回滚记录。

## 6. 高级设置分组与默认策略

| 分组 | 默认展示 | 典型字段 | 新手文案 |
|---|---|---|---|
| 网络与代理 | 摘要 + 折叠 | 连接栈、代理节点、DNS、WebRTC | “实例从哪里联网” |
| 指纹与浏览器标识 | 摘要 + 折叠 | UA、平台、Client Hints、Canvas/Audio | “浏览器如何介绍自己” |
| 语言/时区/地理 | 摘要 + 折叠 | locale、语言、时区、地理位置 | “让语言、时间和网络位置一致” |
| 屏幕/图形/硬件 | 折叠 | 屏幕、DPR、WebGL、字体 | “模拟一台合理的设备” |
| 存储/会话 | 折叠 | Cookie、缓存、LocalStorage、持久化 | “决定实例是否记住登录状态” |
| 启动/性能 | 折叠 | 启动参数、内存、恢复会话 | “决定如何启动和运行” |
| 自动化/调试 | 折叠 | CDP、脚本、调试端口 | “给自动化和排错使用” |
| 诊断/回滚 | 折叠 | 检查记录、配置版本、恢复点 | “出现问题时快速恢复” |

默认只展开有冲突的分组；用户手动打开后记住展开状态。

## 7. MVP 实施顺序与验收标准

### P0：让新手能成功创建实例

1. 新版深色应用壳层和侧边栏信息架构；
2. 自动配置向导（代理/直连二选一）；
3. 本机基线采集和配置摘要；
4. 固定 / 约束随机模式；
5. 配置差异预览、健康检查、草稿和回滚；
6. 实例设置高级分组和字段来源标签。

**P0 验收**

- 新用户无需阅读文档即可完成第一次配置；
- 向导不超过 5 个主步骤；
- 每一个自动修改项都能说明来源；
- 代理失败不会导致半成品实例覆盖已有配置；
- 固定模式连续启动两次，稳定字段一致；
- 随机模式轮换范围受兼容性规则约束；
- 所有冲突均有可读原因和下一步操作。

### P1：提高效率和可观察性

- 指纹模板库和设备簇；
- 配置复制、版本历史和批量检查；
- 网络诊断面板和脱敏导出；
- 命令面板（快速打开实例、代理、诊断）；
- 面向自动化脚本的运行状态联动。

### P2：团队和策略能力

- 团队配置策略；
- 权限分级和审批；
- 策略包导入/导出；
- 更细的轮换策略和审计日志。

## 8. 设计决策边界

- 不把“黑客感”做成高频动画和终端噪音；
- 不把“随机”实现成无约束随机；
- 不承诺“绝对隐身”或“100% 不可检测”；
- 不让新手第一次进入就看到所有高级字段；
